### 3. The hide-button fix (Option B — proper event-driven, commit `f21cf10`, tag `v0.56.2-ct2`)

Problem: Wine/GE reshapes the X input shape with **no wl_surface commit**
(overlay hide, media toggles). Old code only re-read the shape on wl_surface
commit (`src/xwayland/XSurface.cpp` commit listener), so the click-through
region stayed stale until an ALT+TAB restack forced a re-sync. Plus an
empty-shape early return kept the stale region.

Fix (files):
- `src/xwayland/XShapeInputRegion.cpp`: subscribe once per trusted window to
  Shape extension notify (`xcb_shape_select_input`), and on empty/absent shape
  reset to the compositor default (`inputIsInfinite = true`, input cleared)
  instead of early-returning.
- `src/xwayland/XSurface.hpp`: new guard `bool m_inputShapeNotifySubscribed`.
- `src/xwayland/XWM.hpp`: `#include <xcb/shape.h>`, `m_shape` ext pointer,
  `handleShapeNotify(xcb_shape_notify_event_t*)` decl.
- `src/xwayland/XWM.cpp`: prefetch + `m_shape = xcb_get_extension_data(...)`;
  dispatch in `handleSelectionEvent`; `handleShapeNotify` looks the surface up
  by `e->affected_window` and calls `XShapeInputRegion::syncInputRegion`.

### Key technical facts learned (don't re-derive)

- This libxcb's `xcb_shape_select_input(conn, window, enable)` takes only an
  `enable` bitmask, **no separate mask arg**. Input shape kind is bit 2:
  `1 << XCB_SHAPE_SK_INPUT` (`XCB_SHAPE_SK_INPUT == 2`).
- ShapeNotify event field is `affected_window` (not `window`), plus `shape_kind`.
- `SSurfaceState` (src/protocols/types/SurfaceState.hpp) has `CRegion input` +
  `bool inputIsInfinite`; `effectiveInputRegion()` returns the full surface box
  when infinite, else `input ∩ size`. Hit-tester reads
  `SURF->m_current.inputIsInfinite` then `effectiveInputRegion().containsPoint`.
- The X server itself is the packaged `xorg-xwayland` — NOT compositor code. We
  hook events on Hyprland's XWM client side (works with shipped xorg; no need
  to patch xorg).
- `.gitignore` excludes `src/`, `pkg/`, `*.zst` — build outputs are never
  committed; the `.patch` + `PKGBUILD` are the source of truth.
- Patch regeneration procedure (works):
  extract tarball → `git init`/commit → apply old patch → overlay edited files →
  `git diff HEAD > patch`. Seds in `PKGBUILD prepare()` (glaze `find_package`,
  `CMAKE_SKIP_RPATH`) are NOT part of the patch.
- `PKGBUILD` pins patch sha256 — any patch edit MUST bump `sha256sums[1]` or
  `makepkg` fails. `pkgrel` must be numeric-dotted (`3.ct1` was rejected).
